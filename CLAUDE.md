# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Block World" is a Godot **4.7** 3D action game aiming to reproduce the feel of **Cube World** (Picroma): third-person voxel-styled exploration with procedurally generated biomes, trees, and melee combat. Renderer is **Forward Plus**; physics engine is **Jolt Physics**. Code comments are in French. Multiplayer (peer-to-peer, no dedicated server) is a planned direction but **not yet implemented** — the code is kept network-friendly (deterministic generation, no hidden global state).

## Running & editing

No CLI build/test setup — edited and run from the Godot editor.

- Open the project by pointing the Godot 4.7 editor at `project.godot`. Main scene is `Scènes/world.tscn` (`uid://dkunb6ch24p5u`), so pressing Play runs the game.
- Controls: **ZQSD** move (AZERTY), Shift sprints (drains stamina), Space jumps, **Ctrl dodge-rolls** (stamina cost, i-frames), left-click attacks, **right-click uses the class special**, **I toggles the inventory**, **G toggles the lantern**, **Esc opens the pause/options menu**. The `move_*`/`inventory`/`lantern`/`roll` input actions are registered at runtime in `world.gd::_setup_input()` (not in `project.godot`, to avoid corrupting it) — so they won't appear in the editor's Input Map.
- Startup flow: `world.gd` shows the **main menu** (`MainMenu`: pick/create a character, then pick/create a world — Cube World style); nothing is generated until `start_session(character, seed)` runs. The player, `DayNight`, HUD visibility and chunk streaming only exist after that. The pause menu's "Sauvegarder et retour au menu" saves and reloads the scene back to the menu.
- Godot **4.7.1** is on PATH (`~/.local/bin/godot`, a symlink to the Steam install under `~/.local/share/Steam/steamapps/common/Godot Engine/`). Verify changes with the headless smoke test: `godot --headless -s res://tests/smoke.gd` (loads the world with a fixed seed, picks a class, then checks player/camera/lantern/day-night/water invariants — extend it when adding features). A real-render check is possible too: `godot --path . --quit-after 300` (DISPLAY=:0 exists; briefly opens a window, catches shader compile errors that headless's dummy renderer misses). Note: the user's `user://settings.cfg` applies even in tests (e.g. render distance), don't assume export defaults.
- `.godot/` is a generated cache (git-ignored); never edit by hand.

## Architecture

Almost everything is built **in code** (node trees constructed in `_ready()`/`build()`), not authored in `.tscn` scenes. `world.tscn` only holds the light + environment; `player.tscn` is just a root `CharacterBody3D` + script. This keeps the game logic in one place and easy to network later. Consequence: **do not expect meshes/cameras/colliders in the scene files** — look in the scripts.

Core relationships:

- **`Scripts/terrain_gen.gd`** (`class_name TerrainGen`, a `RefCounted`) is the single source of truth for the world. Everything is a **deterministic pure function of `(world_seed, x, z)`**: `get_height`, `get_biome`, `get_color`, `has_tree`. This determinism is deliberate — it is what will let future multiplayer peers share only a seed instead of streaming terrain. **Units: TerrainGen works entirely in cube-index space** — x/z are column indices, `get_height` returns a height in cubes, and a cube is `Chunk.CUBE` (0.5 m) in the world. World↔index conversion is always `roundi(w / Chunk.CUBE)` / `i * Chunk.CUBE`; every consumer that speaks meters (world.gd `_ground_y`, player/enemy `water_depth`, `_update_underwater`, the smoke test) converts explicitly. Noise frequencies are tuned per-index so world-scale relief matches the old 1-m-block terrain (height freq 0.01, amplitudes doubled in cubes), biome regions are ~2.5× larger in world meters (freq 0.0012), and flora probabilities are per-column (divided by 4 when blocks were refined, to keep the same density per m²). The water level lives here too (`WATER_Y`, **in cube units**; world level = `WATER_Y * Chunk.CUBE`): `can_spawn_flora` gates `has_tree`/`get_decoration` (nothing grows underwater or on the 1-cube shoreline band), and `get_color` turns submerged columns into a darkened lakebed with a sand-beach block on the shoreline (except desert/snow biomes).
- **`Scripts/chunk.gd`** (`class_name Chunk`, a `Node3D`) builds one `SIZE`×`SIZE` (16×16) **column** region; with `CUBE := 0.5` a chunk spans 8×8 m. **Optimization is the whole point of this class**: all cubes render through a **single `MultiMeshInstance3D`** (one draw call, per-instance color via `vertex_color_use_as_albedo`), and collision is a **single trimesh** (`ConcavePolygonShape3D`) covering only the top surface + exposed cliff faces — not per-cube colliders. Instances/faces are in chunk-local coords scaled by `CUBE`; `world.gd` positions the chunk node at `(cx*SIZE, 0, cz*SIZE) * CUBE`. Trees and decorations keep their **world** size (they span several small blocks, like Cube World). Columns are only filled down to their lowest neighbor (`_column_bottom`) to skip invisible buried cubes.
- **`Scripts/world.gd`** (on the `World` root of `world.tscn`) is the orchestrator: creates the `TerrainGen`, **streams chunks** around the player (`render_distance` ring, a build queue processed `chunk_build_per_frame` at a time, unloads out-of-range chunks), spawns the player via `Player.new()`, spawns enemies on a timer up to `max_enemies`, registers the ZQSD input actions (`_setup_input`), and owns the HUD (health bar) plus the `OptionsMenu`. Tunables are `@export` vars on the `World` node.
- **`Scripts/options_menu.gd`** (`class_name OptionsMenu`, a `CanvasLayer` with `process_mode = ALWAYS`) is the Esc pause menu: it toggles `get_tree().paused` and releases/captures the mouse (so `player.gd` no longer handles Esc). It is **created at startup** in `world._ready()` — before the class picker — so saved window settings apply on launch; `player` is null until `world.gd` calls `attach_player(player)` (mouse handling and `_apply_game` are null-guarded accordingly). UI is paged: a main page whose buttons navigate to sub-pages ("display", "graphics", "game") via `_show_page`; every sub-page ends with a back button; opening always resets to the main page. All settings live in one `settings` Dictionary, **persisted to `user://settings.cfg`** (loaded in `_ready`, applied via `_apply_all`, saved on every change through `_update_setting` — do NOT rename that back to `_set`, which is a native `Object` virtual). Pages: Affichage (fullscreen, windowed resolution, UI scale via `content_scale_factor` — with an on-screen warning when `Engine.is_embedded_in_editor()`, where window mode/size calls are no-ops), Graphismes (3D `scaling_3d_scale` + upscaling mode bilinear/FSR/FSR2, MSAA, shadow atlas sizes, VSync, `Engine.max_fps`, render distance) and Jeu (mouse sensitivity, volume).
- **`Scripts/player.gd`** (`class_name Player`) is the third-person controller, **driven by `class_id`** (set before `add_child`). The `CLASSES` dict is the single source of truth for the four classes (warrior/ranger/mage/rogue): stats, colors, melee-vs-ranged basic attack, projectile params, and special cooldown. `_ready()` applies the class then builds an **articulated voxel body**: torso/belt/head with eyes, per-class headgear (helmet/hood/pointed hat/bandana), and limbs on pivot nodes (`_arm_l/_arm_r/_leg_l/_leg_r`, built by `_limb` — the box hangs under the joint so rotating the pivot swings the limb; walk/swim animations drive them via `_swing_limbs`). The weapon hangs from the **right arm** (rogue's offhand dagger `_offhand` from the left), the lantern from the left arm. Camera rig: `cam_pivot` → `SpringArm3D` → `Camera3D` (retracts on obstacles; player capsule excluded). **Stamina** (`stamina`, polled by the HUD): sprint drains it, the **dodge roll** (Ctrl, `_start_roll`) costs `ROLL_COST`, gives i-frames (`take_damage` returns while `_roll_timer > 0`) and somersaults the model; regen after `STAMINA_REGEN_DELAY`. Left-click = basic attack; right-click = class special (spin/volley/nova/dash). Movement is camera-relative; the visual `model` rotates toward movement while the body stays unrotated. Emits `health_changed`/`xp_changed`/`leveled_up`/`inventory_changed`/`died`.
- **`Scripts/class_select.gd`** (`class_name ClassSelect`, `CanvasLayer`) is the legacy class-picker screen; it is **no longer shown** — but its `CARDS` const (French class descriptions) is the data source for the main menu's character-creation cards. Keep it in sync when adding classes.
- **`Scripts/enemy.gd`** (`class_name Enemy`) is a data-driven mob. `type_id` (set before `add_child`) selects an archetype from `TYPES` (slime/scout/brute melee, archer ranged) with per-type flags: `hops` (slime moves only by jumps, squash-and-stretch anim), `agile` (stamina-limited **dodge rolls** with i-frames — scout & archer), `zigzag` (scout weaves while approaching). Bodies are built per archetype (`_build_slime` / parametrized `_build_humanoid` with animated limb pivots + gear: bandana/dagger, brows/tusks/fists, bow/quiver). AI: out of aggro they **wander**; in aggro, melee types chase and **jump over 1–2-block obstacles** (`is_on_wall()` + floor → `JUMP_VELOCITY`), the archer kites at `RANGED_KEEP` while strafing sideways and **leads its shots** using the player's velocity, and a soft `_separation()` repulsion keeps them from stacking. They float in lakes (buoyancy via `_gen`, read off the parent World's `gen`). On death `_drop_loot()` (XP always, health 25%, equipment per `drop_chance`) then `queue_free`. Finds the player via the `"player"` group.
- **`Scripts/main_menu.gd`** (`class_name MainMenu`, `CanvasLayer`) is the Cube World-style startup menu: home → characters → worlds, with creation pages (character = name + class card; world = name + seed, blank seed random, text seeds hashed). **Persistence lives here as static funcs** on `user://profiles.cfg` (`ConfigFile`; sections `char_N`/`world_N`, ids from `meta/next_id`): `list_characters`/`list_worlds`/`create_*`/`save_character`/`delete_entry`. A character stores name/class/level/xp/xp_to_next/equipment/inventory (items are plain Dictionaries so they serialize as-is). Emits `start_game(character, world_entry)`; `world.gd` then calls `start_session` and later writes progress back via `save_progress()` (auto on level-up/inventory change, on quit, and on "back to menu" which reloads the scene). Deletion buttons are two-step (✕ → "Sûr ?").
- **`Scripts/pickup.gd`** (`class_name Pickup`, `Area3D`) is a dropped orb (kind `XP` or `HEALTH`). It bobs/spins, magnetizes toward the player within `MAGNET_RADIUS`, applies its effect on `body_entered` (calls `gain_xp`/`heal`), and self-expires after `LIFETIME`.
- **`Scripts/projectile.gd`** (`class_name Projectile`, `Area3D`) is faction-agnostic: `setup(dir, speed, dmg, target_group, color, pass_group)` before `add_child`. It passes through `pass_group` (the shooter's side), damages `target_group`, and dies on terrain or after its lifetime. Enemies shoot with target `"player"`/pass `"enemies"`; the player (ranger/mage) shoots the inverse.

Data flow is one-directional and deterministic: `TerrainGen` (seed) → `Chunk` reads heights/colors/trees → `World` streams chunks + spawns actors. No world persistence or block editing — the world regenerates from its seed.

Progression loop: enemies drop XP/health/**equipment** `Pickup`s → player `gain_xp` → `_level_up` → HUD shows HP bar, XP bar, level, special gauge. `world.gd` spawns a weighted mix of archetypes via `_pick_enemy_type`, and **recycles** enemies beyond `ENEMY_DESPAWN_DIST` (or fallen below y = -30, e.g. off unloaded chunks) — without this the `max_enemies` cap stays filled by mobs abandoned near spawn and spawning silently stops while exploring.

Equipment/loot layer:
- **`Scripts/items.gd`** (`class_name Items`, all-static) defines items as plain Dictionaries: `{slot, rarity, name, damage?, health?, speed?}`. Three slots (weapon/armor/amulet), four rarities with fixed colors/multipliers; `roll_item(level)` scales stats by the player's level at drop time; `describe(item)` renders the bonus summary shown in the UI.
- Player stats are **always derived, never mutated in place**: `player._recompute_stats()` = class base + per-level gains + summed equipment bonuses. Level-ups and equip/unequip both go through it. Equipping a weapon also makes the class weapon glow its rarity color (`_refresh_weapon_visual` rebuilds the weapon rig).
- **`Scripts/inventory_ui.gd`** (`class_name InventoryUI`, CanvasLayer, toggled by `I`) does NOT pause the game — it just frees the mouse (attacks require captured mouse, so clicks are safe). It fully rebuilds on `player.inventory_changed` and auto-closes if the pause menu opens (`_process` watches `get_tree().paused`). Layout rule: the panel sits in a full-rect `MarginContainer` and is positioned by **size flags** (`SHRINK_END`/`SHRINK_CENTER`), never by one-shot anchor presets — its size changes as items are added, and offsets computed at build time would drift off-screen.
- **`Scripts/fx.gd`** (`class_name FX`, static) holds shared effects — `damage_number()` spawns a floating fading `Label3D` (used on enemy hits and player hits).

Swimming: the player swims when the water at its column is chest-deep (`Player.SWIM_ENTER_DEPTH`; `water_depth()` probes the terrain via `player.gen`, a `TerrainGen` reference set by `world.gd` before `add_child`) and stops only when shallower than `SWIM_EXIT_DEPTH` — **hysteresis**, plus a near-surface fade of aim-up lift, so floating at the boundary can't flip-flop between swim and walk (that flicker was a real bug). `_swim_process` replaces gravity with buoyancy toward `FLOAT_DEPTH` (head above surface), moves along the **full camera aim** (pitch included — aim down + forward = dive), Space swims up (near the surface it becomes a hop to climb out), and the model tilts prone. Underwater ambience: `world._update_underwater()` watches the **camera** each frame; when it goes below `WATER_Y` over a submerged column it shows a full-screen tint (`CanvasLayer` layer 0, under the HUD) and sets `DayNight.underwater`, which swaps the fog for a dense blue-green one (`UNDERWATER_FOG_DENSITY`, darkened at night, `fog_sky_affect` 1.0) and tints the ambient light; base fog values are captured in `DayNight._ready` and restored on exit.

Aesthetics: environment (fog, glow, ACES tonemap, warm sun) lives in `world.tscn`; water (cosmetic lakes at `TerrainGen.WATER_Y`) is built **per chunk**: `Chunk._build_water()` emits one quad per submerged column (SurfaceTool + `generate_tangents`, needed by the shader's NORMAL_MAP), so lakes only exist where terrain is actually below water — there is no global plane following the player anymore. All chunks share ONE `ShaderMaterial` created by `world._make_water_material()` (`world.gd::WATER_SHADER`): vertex waves + animated normal ripples + fresnel, anchored in **world** coordinates so edges match between columns and chunks. Per-biome micro-decorations (grass/flowers/cacti/rocks) come from `TerrainGen.get_decoration` and render as a second per-chunk MultiMesh; trees get deterministic scale variation. `TerrainGen.rand01(x, z, salt)` is the shared deterministic hash — use a distinct `salt` per feature so rolls stay independent.

Day/night cycle: **`Scripts/day_night.gd`** (`class_name DayNight`, a plain `Node` created by `world._make_day_night()`, cycle duration via the `day_length` @export on `World`, default 900 s). Everything derives from `time_of_day` (0 = midnight, 0.25 = dawn, 0.5 = noon). At startup it **replaces** the `ProceduralSkyMaterial` from `world.tscn` with its own sky shader (`DayNight.SKY_SHADER`): gradient sky, drifting fbm clouds, night stars, and a sun/moon disk drawn from `LIGHT0` (always aligned with the `DirectionalLight3D`). Per frame it animates the light (elevation always positive via `asin(abs(sin))` — at night the same light becomes a cool dim moon), the sky uniforms, fog color, and `ambient_light_color` (source forced to `AMBIENT_SOURCE_COLOR`: diffuse moonlight at night instead of pitch black). It pauses with the tree (plain `_process`).

Group conventions: player is in group `"player"`, enemies in `"enemies"`. Combat, AI, loot, and projectiles rely on these groups + duck-typed methods `take_damage(amount, from)`, `gain_xp(amount)`, `heal(amount)`. The player broadcasts its stats to the HUD via `broadcast_stats()` after `world.gd` connects the signals (so the initial values aren't missed).

## Conventions

- Scene files live under `Scènes/` (accented dir — keep it; `res://Scènes/...` paths and UIDs depend on it). `tree.tscn` is still an authored scene (instanced per-tree by chunks); `cube.tscn` is now **unused** (terrain uses a `MultiMesh`, not cube-scene instances).
- To keep the chunk size consistent, `world.gd` reads `Chunk.SIZE` rather than hardcoding it.
- When moving/renaming scenes or scripts, do it via the editor so `uid://` references stay valid instead of hand-editing paths.

## Sensible next steps (from the Cube World goal)

- **Multiplayer P2P**: Godot high-level multiplayer over ENet (`MultiplayerPeer`/`MultiplayerSpawner`/`MultiplayerSynchronizer`), host/join by IP. Sync the seed once; replicate only player/enemy state. The deterministic `TerrainGen` already supports this.
- More abilities per class, smoothing biome-boundary height jumps, and swapping the trimesh collider for greedy-meshed collision if profiling demands it. (Classes, loot/equipment/inventory & leveling, day/night cycle, water/shoreline generation, swimming are done.)
